Privacy policy

LogLens is a private, locally operated application maintained by Amit Desai for website-log analysis and operational email review.

Effective date: 24 October 2026

1. Scope and operator

This policy describes the LogLens application and this public information website. The dashboard is not hosted on this website and is not available for public registration. Contact the operator at gtierrors@gmail.com for support, access or deletion questions.

2. Google account data accessed

When the operator connects the designated Gmail account, LogLens uses Google OAuth and the https://www.googleapis.com/auth/gmail.modify scope. It accesses the account email address to confirm the connected account, message IDs, labels, read status, and message metadata including Subject and Date headers. It extracts IP addresses from alert subjects to compare with imported website logs.

The error-email workflow requests message metadata, not full email bodies or attachments. LogLens receives and stores OAuth credentials, including access and refresh tokens, to maintain the authorised connection. It does not collect the Gmail password.

3. Why Gmail access is needed

The operator manually starts the email-review workflow. LogLens finds unread messages outside Spam and Trash and checks their subject IP addresses against the corresponding log date.

  • Messages matching configured low-success-response rules are moved to Trash.
  • Other messages associated with rogue requests are starred and marked as read.
  • Messages without rogue requests receive the “To Check & Delete” label, are marked as read and archived.
  • Messages without a usable IP address or sufficient log data are left for review.

The application can create the review label if it does not exist. It does not send emails or permanently delete Gmail messages through the API. Messages in Trash remain subject to Gmail's own retention and deletion behaviour.

4. Other information processed

Imported IIS logs can contain IP addresses, request timestamps, URLs, query strings, referrers, user agents and response information. User Insights stores derived search counts, estimated journeys and selected order/product details obtained from a read-only order API. Search terms and URLs may contain information entered by website users.

A separate Yahoo import workflow can read selected unread email messages and download log attachments using locally stored credentials. This is separate from the Google OAuth connection.

5. Storage, retention and security

Processing occurs on the operator's computer and configured database. Google OAuth configuration and tokens are stored in local private files with owner-only permissions and are excluded from the source repository. Connections to Google's APIs use HTTPS.

Gmail review results, including message IDs, extracted IP addresses, dates and outcomes, are held in the dashboard session; the current email-review workflow does not write a separate persistent copy of Gmail bodies or attachments. The messages themselves remain in Gmail until removed under the account's settings or by its owner.

OAuth credentials remain locally until the operator removes them. Imported logs and extracted User Insights records are retained until the operator deletes them; no automatic 90-day log deletion is currently enabled. User Insights snapshots have no automatic expiry. Any operator-managed backups must be handled separately. Local storage is not a claim of encryption at rest.

6. Sharing and permitted use

LogLens uses Google account data only to provide its email-review functionality. It does not sell Google user data, use it for advertising, or use it to train general-purpose AI or machine-learning models. Google user data is not sent to the order API, Yahoo, or this public website. The authorised operator can view the review results; the application does not provide third parties with access to the mailbox data.

LogLens's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

7. Revoking access and deleting local data

The account owner can revoke LogLens's Google access from Google Account third-party connections. Revocation prevents further authorised API access, but does not undo label, read-status, archive or Trash changes already made.

To remove local credentials, stop LogLens and delete its Gmail token file from the application's .loglens-private folder. To remove other local records or backups, contact the operator. Revoking Google access alone does not delete imported IIS logs, saved insights or backups. Emails can be managed directly in Gmail.

8. This public website

These information pages contain no sign-in form, advertising, analytics scripts or application tracking cookies. They are hosted on GitHub Pages. GitHub may process technical request information, such as visitors' IP addresses, under its privacy statement. No application credentials, private logs, order records or mailbox data are hosted here.

9. Changes and contact

This policy will be updated when the application's data practices change. The effective date above identifies the current version. For questions or requests, email gtierrors@gmail.com.
